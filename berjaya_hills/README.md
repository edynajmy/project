## 🌿 Project Overview

The **Berjaya Hills Event Management System** is a web-based platform developed to support event planning, venue reservations and administrative operations within a resort environment.

The system provides a centralised platform where users can explore available venues, submit event booking requests, manage their reservations and monitor booking progress.

On the administrative side, authorised personnel can manage bookings, events, venues, facilities, user accounts, resort activities and other operational information through dedicated management interfaces.

The platform combines a public-facing resort website with an internal event management system, creating a more organised approach to coordinating event-related activities.

### Main Purpose

The primary purpose of this project is to:

- Centralise event booking and management activities.
- Simplify the process of requesting resort venues.
- Improve communication between users and management.
- Provide visibility into booking statuses and event schedules.
- Organise venue, facility and event information.
- Support administrative monitoring and reporting.

### Target Users

The system is designed for:

- Individuals and organisations interested in organising events.
- Registered users submitting venue booking requests.
- Resort management personnel.
- Event and operational staff.
- Human Resources personnel.
- Authorised administrative and technical personnel.

---

## ❗ Problem Statement

Managing event reservations and resort operations involves coordinating different types of information, including event schedules, venue availability, facilities, user details and booking requirements.

Without a centralised platform, these processes may become difficult to coordinate and monitor.

Some of the operational challenges addressed by this system include:

1. **Fragmented booking information**

   Event details and reservation information can become difficult to organise when managed through separate processes.

2. **Difficult booking monitoring**

   Users may have limited visibility into the progress and status of their booking requests.

3. **Venue management complexity**

   Information about venues, facilities, capacity and availability needs to be maintained consistently.

4. **Scheduling coordination**

   Event schedules require proper organisation to support operational planning and reduce scheduling conflicts.

5. **Administrative workload**

   Managing user accounts, booking approvals, event information and operational records requires an organised administrative interface.

The system addresses these challenges by providing a centralised web application for event planning and management.

## 🎯 Project Objectives

The objectives of this project are:

1. To develop a centralised web-based event management platform for resort operations.
2. To provide users with an organised interface for exploring venues and submitting event booking requests.

## 🏗️ System Architecture

The application follows a server-rendered PHP architecture.

Users access the application through a web browser. PHP processes requests, validates user permissions and communicates with the MySQL database through PDO.

The application returns HTML pages styled with CSS and enhanced with JavaScript.

## 🗄️ Database Design

### Database Information

| Item | Details |
|---|---|
| Database Name | `berjaya_hills` |
| Database System | MySQL |
| Storage Engine | InnoDB |
| Character Set | utf8mb4 |
| Collation | utf8mb4_unicode_ci |
| Main Schema | `database/schema.sql` |

The database is designed to support user accounts, role permissions, event records, venue information, booking requests, facilities and administrative operations.

### Main Database Tables

The supplied main schema defines 43 tables.

| Category | Tables | Purpose |
|---|---|---|
| User Management | `users`, `roles`, `permissions`, `user_roles`, `role_permissions`, `password_resets` | User accounts, authentication, role assignments and permissions |
| Location Management | `locations`, `location_categories`, `location_images`, `location_gallery` | Resort location information and photographs |
| Venue Management | `venues`, `venue_images`, `venue_facilities`, `venue_maintenance` | Venue information, images, facilities and maintenance |
| Facility Management | `facilities`, `room_types` | Facilities, equipment and room information |
| Event Management | `events`, `event_categories`, `event_venues`, `event_timeline_items`, `event_financial_estimates`, `event_gallery` | Event details, categories, schedules, financial estimates and media |
| Booking Management | `bookings`, `booking_rooms`, `booking_facilities`, `booking_food`, `booking_status_history`, `booking_change_history`, `booking_change_requests` | Booking records, selected services, status history and change requests |
| Food Management | `food_menus` | Catering and food package information |
| Activity Management | `csr_activities`, `day_tripper_activities`, `staff_activities`, `training_sessions` | Resort activities, staff programmes and training records |
| Gallery Management | `gallery_albums`, `gallery_images` | Album and image management |
| Notifications | `notifications`, `notification_templates`, `user_notification_preferences` | Notification records and preferences |
| Administration | `system_settings`, `audit_logs`, `email_logs`, `contact_inquiries` | System configuration, audit records, email logs and enquiries |

### Important Relationships

The database uses primary keys and foreign keys to maintain relationships between records.

Examples:

- A user can have multiple assigned roles through `user_roles`.
- Roles can have multiple permissions through `role_permissions`.
- A user can create multiple event records.
- An event can be associated with multiple venues through `event_venues`.
- A user can create multiple bookings.
- A booking belongs to an event.
- A booking can contain multiple selected facilities.
- A booking can contain multiple room selections.
- A booking can contain catering selections.
- A booking can have multiple status history records.
- A venue can contain multiple associated facilities.
- A gallery album can contain multiple images.

### Database Views

The main schema also defines three views:

| View | Purpose |
|---|---|
| `vw_calendar_events` | Provides consolidated event information for calendar displays. |
| `vw_booking_summary` | Provides consolidated booking, user, event and venue information. |
| `vw_upcoming_public_events` | Retrieves upcoming confirmed public events. |

The project contains additional SQL scripts for database extensions and migrations.

## ⚙️ Installation Guide

Follow these steps to install the project locally.

### Step 1: Clone the Repository

Open your terminal and run:

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
```

Navigate into the project directory:

```bash
cd YOUR_REPOSITORY
```

### Step 2: Install XAMPP

Download and install XAMPP.

Start the following services:

- Apache
- MySQL

### Step 3: Move the Project into htdocs

Copy the project folder into the XAMPP web directory.

Example:

```text
C:\xampp\htdocs\berjaya_hills\
```

### Step 4: Create the Database

Open phpMyAdmin:

```text
http://localhost/phpmyadmin
```

Create a new database named:

```sql
berjaya_hills
```

Recommended database settings:

```sql
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci
```

### Step 5: Import the Main Database Schema

Select the `berjaya_hills` database.

Open the Import tab and import:

```text
database/schema.sql
```

This creates the main tables, relationships, views and initial reference records.

**Warning:** The main schema contains DROP TABLE statements. Use it only when creating a fresh database. Do not run it against an existing database containing information that must be preserved.

### Step 6: Apply Required Database Migrations

After importing the main schema, execute the following SQL files in order:

**Migration 1**

```text
database/migrations/v118_booking_other_venue.sql
```

**Migration 2**

```text
database/migrations/v119_other_venue_display.sql
```

**Migration 3**

```text
database/add_venue_reviews.sql
```

**Migration 4**

```text
database/add_event_archive_features.sql
```

These scripts provide additional database structures required by functionality present in the current PHP source code.

### Step 7: Configure Database Connection

Open:

```text
config/config.php
```

The current local development configuration is:

```php
define('BASE_URL', '/' . basename(dirname(__DIR__)) . '/');

define('APP_NAME', 'Berjaya Hills Resort');

define('DB_HOST', '127.0.0.1');
define('DB_NAME', 'berjaya_hills');
define('DB_USER', 'root');
define('DB_PASS', '');

define('TIMEZONE', 'Asia/Kuala_Lumpur');
```

Update the database settings according to your local MySQL configuration.

For example:

```php
define('DB_HOST', '127.0.0.1');
define('DB_NAME', 'berjaya_hills');
define('DB_USER', 'root');
define('DB_PASS', 'your_local_database_password');
```

Do not commit real production credentials to GitHub.

### Step 8: Check Folder Permissions

Ensure the following directories are writable by the web server when their upload functionality is used:

```text
assets/gallery/
uploads/profile/
```

The application needs appropriate permissions to store uploaded gallery images and profile photographs.

### Step 9: Verify PHP Configuration

Check that the required PHP extensions are enabled:

```text
PDO
PDO MySQL
Fileinfo
```

Password recovery also uses PHP's native `mail()` function. A properly configured local or production mail transport is needed for email delivery.
