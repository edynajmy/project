## 🌟 Project Overview

**EDYLIFE** is a personal life management web application designed to help individuals organise their daily activities, manage tasks, plan their work, track entertainment interests and preserve personal memories.

Built around the concept of having one personal digital space, EDYLIFE combines several everyday productivity and lifestyle management tools into a single dashboard.

Instead of switching between multiple applications to manage different aspects of daily life, users can access their personal workspace through one centralised interface.

The application provides dedicated modules for daily planning, activities, movie and drama tracking, work management, photo organisation, calendar management and personal journaling.

EDYLIFE is designed with a premium, minimalist interface that combines a dark visual environment, elegant typography and subtle gold accents to create a comfortable and visually consistent user experience.

### Project Vision

**Your World. Your Story.**

EDYLIFE aims to provide a personal digital environment where productivity, entertainment, memories and everyday experiences can exist together.

### Main Purpose

The primary purpose of EDYLIFE is to:

- Organise daily activities and personal schedules.
- Manage tasks and track completion progress.
- Plan work items, projects and deadlines.
- Maintain a personal movie and drama watchlist.
- Store and organise photographs.
- Provide a calendar for viewing personal journal entries.
- Record daily thoughts, experiences and memories.
- Create a personalised digital workspace.

### Target Users

EDYLIFE is designed primarily for:

- Individuals who want to organise their everyday activities.
- People who manage personal and work-related tasks.
- Movie and drama enthusiasts.
- Individuals who enjoy documenting personal memories.
- Users who prefer having productivity and lifestyle tools in one place.

## ❗ Problem Statement

Modern daily life involves managing multiple responsibilities, interests and personal activities.

People often use different applications for task management, entertainment tracking, photo storage, calendar scheduling and journaling.

Managing these activities across separate platforms can make personal organisation less convenient.

Some common challenges include:

1. **Fragmented personal information**

   Tasks, schedules, entertainment lists and personal memories are often stored in different applications.

2. **Difficulty managing daily activities**

   Without a structured planning interface, it can be difficult to organise activities and maintain a clear daily schedule.

3. **Unorganised task management**

   Personal responsibilities and work-related tasks require different priorities, deadlines and progress tracking.

4. **Entertainment tracking**

   Movie and drama enthusiasts may need a dedicated place to record what they have watched, what they are currently watching and what they plan to watch.

5. **Scattered personal memories**

   Photographs and personal experiences can become difficult to organise when they are stored without meaningful categories or folders.

6. **Limited personal documentation**

   Individuals may want to record daily experiences, thoughts and moods in an organised personal journal.

EDYLIFE addresses these challenges by bringing different personal management functionalities together within one web-based application.

## 🏗️ System Architecture

EDYLIFE follows a server-rendered PHP architecture with a MySQL database.

The application processes user requests through PHP action handlers and retrieves or updates records using PDO.

HTML generates the page structure, CSS controls the visual presentation, and JavaScript provides client-side interactions.

### Architecture Diagram

```text
                 USER
                   |
                   v
             WEB BROWSER
                   |
                   v
          PRESENTATION LAYER
             HTML / CSS
             JavaScript
                   |
                   v
           APPLICATION LAYER
                  PHP
                   |
          +--------+--------+
          |                 |
          v                 v
      PAGE MODULES      ACTION HANDLERS
          |                 |
          |           CREATE / UPDATE
          |           DELETE / UPLOAD
          |           STATUS CHANGES
          |                 |
          +--------+--------+
                   |
                   v
             PDO DATABASE
               CONNECTION
                   |
                   v
              MYSQL SERVER
                   |
                   v
             NOIRLIFE DATABASE
```

### Main Application Components

| Component | Responsibility |
|---|---|
| Presentation Layer | Displays the user interface |
| PHP Page Modules | Retrieves and displays application data |
| Action Handlers | Processes create, edit, delete and upload operations |
| Bootstrap | Initialises database connection and shared functions |
| PDO | Handles database communication |
| MySQL | Stores application information |
| Upload Directories | Store photographs, posters and cover images |

## 🗄️ Database Design

### Database Information

| Item | Details |
|---|---|
| Database Name | `noirlife` |
| Database System | MySQL |
| Storage Engine | InnoDB |
| Character Encoding | utf8mb4 |
| Connection Method | PDO |
| Configuration | `config/database.php` |
| Timezone | Asia/Kuala_Lumpur |

**Important naming note:** Although the application is now branded as EDYLIFE, the internal database name, local installation folder and some browser storage identifiers retain the legacy name `noirlife` for compatibility.

### Main Database Tables

The PHP application references the following main tables:

| Table | Purpose |
|---|---|
| `tasks` | Stores personal dashboard tasks |
| `activities` | Stores scheduled daily activities |
| `media_watchlist` | Stores movie, drama and other entertainment records |
| `photo_folders` | Stores photo folder information |
| `photos` | Stores photograph metadata |
| `daily_entries` | Stores personal journal entries |
| `work_items` | Stores work tasks and project information |
| `profile_settings` | Stores personal profile and workspace settings |

### Database Relationships

The main application relationships include:

- A photo folder can contain multiple photographs.
- Each photograph belongs to a photo folder.
- Each work item contains its own task details, priority and status.
- Each activity contains a scheduled date and time.
- Each journal entry is associated with a specific date.
- Each media record stores its category, viewing status and optional rating.

### Database Migrations

The supplied project contains two SQL migration files.

| SQL File | Purpose |
|---|---|
| `noirlife_v1_4_5_journal.sql` | Creates the `daily_entries` table for the Calendar and Daily Journal modules. |
| `noirlife_v1_5_work_planner.sql` | Creates the `work_items` table for the Work Planner module. |

### Automatically Created Table

The `profile_settings` table is created automatically by:

```text
includes/bootstrap.php
```

The application also inserts a default profile record if one does not exist.

### Database Schema Availability

**Important installation limitation:**

The supplied ZIP does not include the original base database schema containing the initial tables required by the application.

The following baseline tables are referenced by the source code but their original creation SQL is not included in this archive:

- `tasks`
- `activities`
- `media_watchlist`
- `photo_folders`
- `photos`

Therefore, a complete fresh database installation requires the original base SQL export or an equivalent verified database backup.

Do not assume that importing the two supplied migration files alone is sufficient to install the entire application.

## ⚙️ Installation Guide

### Step 1: Clone the Repository

Open your terminal:

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
```

Navigate to the project folder:

```bash
cd YOUR_REPOSITORY
```

### Step 2: Install XAMPP

Download and install XAMPP.

Start:

- Apache
- MySQL

### Step 3: Move the Project into htdocs

Place the extracted project inside:

```text
C:\xampp\htdocs\noirlife\
```

The application retains the `noirlife` directory name for compatibility with the existing URL and configuration logic.

### Step 4: Prepare the Database

Open phpMyAdmin:

```text
http://localhost/phpmyadmin
```

Create a database named:

```sql
noirlife
```

Recommended database settings:

```sql
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci
```

**Important:** You must first obtain and import the original base database schema or a verified database export. The supplied ZIP does not contain the original `noirlife.sql` file.

### Step 5: Import Database Migrations

After the original database has been restored, import the following migration files in order.

**Migration 1 — Calendar & Daily Journal**

```text
database/noirlife_v1_4_5_journal.sql
```

This creates:

```text
daily_entries
```

**Migration 2 — Work Planner**

```text
database/noirlife_v1_5_work_planner.sql
```

This creates:

```text
work_items
```

Both scripts use `CREATE TABLE IF NOT EXISTS` and are intended to preserve existing records.

### Step 6: Configure Database Connection

Open:

```text
config/database.php
```

The local development configuration uses:

```php
return [
    'host' => '127.0.0.1',
    'database' => 'noirlife',
    'username' => 'root',
    'password' => '',
];
```

Update the credentials according to your local MySQL configuration.

For example:

```php
return [
    'host' => '127.0.0.1',
    'database' => 'noirlife',
    'username' => 'root',
    'password' => 'your_database_password',
];
```

Never publish production database credentials in a public repository.

### Step 7: Check Upload Directories

Ensure that the web server can write to the required upload directories:

```text
uploads/
├── cover/
├── photos/
└── posters/
```

The application uses these directories for:

- Dashboard and module cover images.
- Personal photographs.
- Movie and drama posters.

### Step 8: Configure PHP Upload Limits

The application supports the following upload limits:

| Upload Type | Maximum Size |
|---|---|
| Movie posters | 5 MB per file |
| Personal photographs | 5 MB per file |
| Cover photographs | 8 MB per file |
| Multiple photo upload | Maximum 10 files per request |

Ensure that PHP configuration permits these uploads.

Example `php.ini` settings:

```ini
upload_max_filesize = 8M
post_max_size = 60M
max_file_uploads = 20
```

Restart Apache after changing PHP configuration.
